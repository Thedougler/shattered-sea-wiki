# Traveling Event System

> Agent use: Read before creating travel events, sea encounters, or route pressure.

## Fast Rules

- Travel events should express route, weather, faction pressure, or PC hooks.
- Use distance and danger to set event density.
- Every event needs decision, cost, reveal, or consequence.
- Avoid filler encounters that do not change anything.


A practical tool for making travel feel like part of the story, not the gap between real sessions. Replaces random encounter tables with curated scenes drawn from the party's own threads.

## The Core Idea

Travel events are not random encounters. They are selected or designed for this specific party, drawn from backstories, tensions, and unresolved threads. A random encounter fills time. A travel event advances something.

## Distance Framework

Stop giving players exact distances. Use three tiers:

| Distance | Events to Prep |
|----------|---------------|
| Close | 1 event |
| Far | 2–3 events |
| Very Far | up to 5 events |

"A few days" beats "four days." Exact numbers pull players into calendar math instead of story.

## Event Design

Each event should pull on something that already matters to a specific character. Ask: What backstory threads are unresolved? What tensions exist within the party? Which character hasn't had a meaningful moment recently?

Events don't need resolution. They add complications, questions, and things to carry forward — a letter with no explanation, a face from the past, a choice that forces a character to reveal something.

## Building Events

Remove template specifics; replace with your party's actual threads. The system gives you a handful of moments per journey where something that already matters gets a little more complicated. That's what makes travel feel like part of the story.
